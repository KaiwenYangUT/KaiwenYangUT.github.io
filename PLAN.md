## 1. Design spec

### 1.1 Palette: Matcha (default)

All contrast ratios are computed against WCAG 2.x. Text tokens are ≥4.5:1 and graphic tokens are ≥3:1.

| Token | Light | Dark | Use | Contrast (L / D) |
|---|---|---|---|---|
| `--bg` | `#F4F1E8` | `#1B1A16` | page (paper / warm charcoal) | n/a |
| `--surface` | `#ECE8DB` | `#24231E` | dataset card, table stripes, code | n/a |
| `--ink` | `#1F1D18` | `#ECE8DC` | body text | 14.9 / 14.2 |
| `--muted` | `#68645A` | `#A6A192` | metadata, captions | 5.2 / 6.7 (≥4.8 on surface) |
| `--rule` | `#D6D1C2` | `#38362F` | hairlines (decorative) | 1.35 / 1.44 |
| `--rule-strong` | `#8C8576` | `#716B5F` | chart axes, focus-adjacent lines | 3.24 / 3.29 |
| `--accent` | `#4A6B2A` | `#A9C77E` | links, active-nav dot, timeline bars | 5.4 / 9.3 |
| `--accent-tint` | `#E2E6CF` | `#2C3323` | tag chips and hover backgrounds | accent on tint 4.8 / 7.0 |
| `--strawberry` | `#A8405A` | `#EE9AAE` | **easter egg only**: `actual_order` value and the 404 page | 5.2 / 8.2 |
| `--selection` | `#F2C9D2` | `#5A2F3A` | `::selection` (strawberry matcha: green site, pink highlight) | ink on it 11.3 / 9.0 |

Accent discipline: the green appears only in links, the active-nav dot, the "now" markers and the timeline bars. Never use it for large fills.

**Alternative sets** (swap the values in `tokens.css`; all pass AA):
- **Plum.** Light: bg `#F6F1E9`, surface `#EFE8DC`, ink `#221C17`, muted `#6B6158`, rule `#D9CFC1`, accent `#7A2E52` (8.0:1). Dark: bg `#1D1916`, surface `#26211D`, ink `#EDE6DB`, muted `#A89D90`, rule `#3A332D`, accent `#E39BBE` (8.1:1).
- **Ochre.** Light: bg `#F7F3EC`, surface `#EEE8DD`, ink `#1E1A16`, muted `#6A6157`, rule `#DAD1C3`, accent `#8A5A00` (5.4:1). Dark: bg `#1C1915`, surface `#25211C`, ink `#EEE7DA`, muted `#A99E8F`, rule `#3B342C`, accent `#E0B456` (9.0:1).

### 1.2 Typography

None of these fonts are used by the reference site.
- **Display and body: Schibsted Grotesk** (variable, 400–900; `@fontsource-variable/schibsted-grotesk`). A Scandinavian newspaper grotesk: Swiss-leaning, with more character than Inter.
- **Metadata: IBM Plex Mono** (400 and 500; `@fontsource/ibm-plex-mono`), for dates, course codes, tags, the dataset card and axis ticks.
- Tabular numerals (`font-variant-numeric: tabular-nums`) wherever dates or grades line up.

Type scale (ratio about 1.25, fluid at the top end):
| Token | Size | Use |
|---|---|---|
| `--step--1` | 0.8125rem (13px) | mono metadata, set in caps with `letter-spacing: .04em` for section labels |
| `--step-0` | 1.0625rem (17px), line-height 1.55 | body |
| `--step-1` | 1.3125rem (21px) | entry titles |
| `--step-2` | 1.625rem (26px) | page subtitles |
| `--step-3` | clamp(1.75rem, 3.5vw, 2.25rem) | page titles |
| `--step-4` | clamp(2.5rem, 7vw, 4.5rem), weight 700, tracking −0.02em | Home name only |

### 1.3 Spacing and grid
- Spacing scale (4px base): `--s-1: 4px`, `--s-2: 8px`, `--s-3: 12px`, `--s-4: 16px`, `--s-5: 24px`, `--s-6: 32px`, `--s-7: 48px`, `--s-8: 64px`, `--s-9: 96px`.
- Container max width is `72rem` with side padding `clamp(16px, 4vw, 40px)`, so the gutter is 16px at 360px.
- 12-column grid with 24px gaps (16px below 720px). **The asymmetric index layout:** columns 1–3 hold the "index column" (section number, mono dates and codes, sticky on desktop) and columns 4–12 hold the content. Below 720px it collapses to one column and the index metadata sits above each entry.
- Breakpoints: 480, 720 and 1024px. Test at 360px.
- Hairlines are 1px `--rule` and separate every list row. No cards, no shadows, and border-radius is 0, except 2px on chips.
- Section labels follow the pattern `02 / EDUCATION` in mono `--muted`.

### 1.5 Photo treatment
- `scripts/process-photo.mjs` uses **sharp**. It reads `assets-src/portrait-original.jpg` and the crop box from `assets-src/portrait.config.json`. Default: 4:5, top ~8% to just below the hood V. It converts to greyscale, slightly boosts contrast, then maps each luminance value onto a **duotone from `--ink #1F1D18` (shadows) to `--bg #F4F1E8` (highlights)** in a raw-pixel pass. This turns the saturated blue into a warm mid-tone that belongs to the palette.
- Outputs go to `public/images/portrait-{480,800,1200}.{avif,webp,jpg}` plus `portrait-og.jpg`. They're used through `<picture>` with `srcset`/`sizes`, with explicit `width`/`height` (no CLS), `fetchpriority="high"` on Home, and alt text: "Kaiwen Yang, smiling, in a University of Toronto convocation gown."
- Shown as a rectangle with a 1px `--rule` frame and no radius. In dark mode, `filter: brightness(.92)` so it doesn't glare.
- **Swapping in a casual photo later:** replace the original, adjust the crop JSON, run `npm run photo`, and commit. No component changes.

## 2. Content model (`src/content/types.ts`)

```ts
export type Section = 'education' | 'work' | 'research' | 'projects' | 'teaching';
export type YearMonth = `${number}-${'01'|'02'|'03'|'04'|'05'|'06'|'07'|'08'|'09'|'10'|'11'|'12'}`;
export type DateLike = YearMonth | `${number}`;           // '2025' allowed for year-only entries
export type Tag = string;                                // lowercase-kebab, e.g. 'time-series'

export interface Link {
  label: string;
  href: string;
  kind?: 'repo' | 'demo' | 'report' | 'paper' | 'slides' | 'site';
}

/** Fields every entry shares. `id` doubles as the URL anchor (#id) and the cross-link key. */
export interface BaseEntry {
  id: string;
  sections: Section[];          // every page this entry appears on (no duplication)
  title: string;                // role, degree, or project name
  org?: string;
  location?: string;
  start: DateLike;
  end?: DateLike | 'present';
  expected?: boolean;           // e.g. MEng end date
  summary?: string;             // one line
  bullets?: string[];
  tags: Tag[];
  links?: Link[];
  related?: string[];           // ids of other entries → "Also in …" links
  draft?: boolean;              // excluded from build
}

export interface Award { name: string; year: number; amount?: string }
export interface CourseGrade { name: string; grade?: string }

export interface EducationEntry extends BaseEntry {
  kind: 'education';
  degree: string;               // "MEng", "HBSc"
  field: string;
  distinction?: string;         // "with High Distinction"
  gpa?: { value: string; scale: string; label?: string };   // label: "Major GPA"
  honours?: string[];           // "Dean's List Scholar (2021–2025)"
  awards?: Award[];
  coursework?: CourseGrade[];
}

export interface ResearchFacet {
  question: string;
  supervisor?: string;
  lab?: string;                 // or department
  role: string;
  methods: Tag[];
  outputs: string[];
  funding: 'paid' | 'unpaid' | 'course';
}

export interface WorkEntry extends BaseEntry {
  kind: 'work';
  employment: 'internship' | 'part-time' | 'contract' | 'full-time';
  research?: ResearchFacet;     // present ⇔ 'research' ∈ sections
  seeAlsoRoute?: '/teaching';   // compact row pointing elsewhere (TA summary)
}

export interface ResearchEntry extends BaseEntry { kind: 'research'; research: ResearchFacet }

export interface ProjectEntry extends BaseEntry {
  kind: 'project';
  context: 'self-directed' | 'course' | 'hackathon';
  course?: string;
  stack: Tag[];
  highlights?: string[];        // mono key-numbers row
}

export type Entry = EducationEntry | WorkEntry | ResearchEntry | ProjectEntry;

/* ---------- Teaching ---------- */
export type Season = 'Winter' | 'Summer' | 'Fall';
export interface Term { season: Season; year: number }

export interface Course {
  code: string;                 // 'STA313H1' (display 'STA313')
  title: string;                // official calendar title
  description: string;          // verbatim from calendar
  sourceUrl: string;            // https://artsci.calendar.utoronto.ca/course/sta313h1
  retrieved: string;            // ISO date
  verified: boolean;            // false → UI shows "description unverified"
}

export interface TeachingAppointment {
  id: string;
  term: Term;
  courseCode: string;           // FK → Course.code
  role: 'Teaching Assistant' | 'Head TA' | 'Course Instructor';
  institution: 'University of Toronto';
}
```

Selectors (`src/lib/selectors.ts`): `entriesFor(section)`, `byId(id)`, `relatedOf(entry)`, `termsForCourse(code)`, `termStatus(term, buildDate) → 'past'|'current'|'upcoming'` (Winter = Jan–Apr, Summer = May–Aug, Fall = Sep–Dec), `sortByStartDesc`.

`src/lib/time.ts` exports `BUILD_DATE`, injected at build time through Vite `define`. Nothing calls `new Date()` during render.

**Validation** (Vitest, `tests/content.test.ts`; it runs in CI before the build):
- ids are unique
- every `related` id resolves, and links run both ways or a warning is printed
- `'research' ∈ sections` ⇔ a `research` facet exists
- every `courseCode` exists in `courses.ts`
- dates are well-formed and `start ≤ end`
- **privacy check:** no phone-number pattern (`/\+?1?[\s-]?\(?778\)?|\d{3}[\s.-]\d{3}[\s.-]\d{4}/`) appears in `src/content/**` or in `build/client/**` after the build

## 4. Phased tasks (one agent session each)

### Phase 1: Repo, scaffold, pipeline (prove deploy first)

## 5. Deployment (existing repo, no `gh`)
1. `git clone https://github.com/KaiwenYangUT/KaiwenYangUT.github.io.git ~/Desktop/KaiwenYangUT.github.io`. Git will warn that the repo is empty, which is expected.
2. After Phase 1: `git branch -M main && git add -A && git commit && git push -u origin main`.
   - **Auth:** pushing over HTTPS needs a credential. When git prompts, use a **Personal Access Token**: either a classic token with the `repo` + **`workflow`** scopes, or a fine-grained token with Contents R/W and **Workflows R/W** on this repo. Without workflow permission, the push that adds `.github/workflows/deploy.yml` is rejected. macOS Keychain (`osxkeychain`) remembers the token.
3. **Your manual step:** in the repo, go to **Settings → Pages → Build and deployment → Source: GitHub Actions**. Then re-run the workflow from the Actions tab, or push again.
4. Check the Actions run is green, then open `https://kaiwenyangut.github.io/`.
5. **Deep links:** solved by prerendering, since each route is a real `route/index.html`. GitHub Pages may 301 `/education` to `/education/`, which is harmless. Set `canonical` to the trailing-slash form so they agree. `404.html` handles unknown paths.
6. **Custom domain later:** add it under Settings → Pages → Custom domain and set the DNS records (CNAME → `kaiwenyangut.github.io`, or A/AAAA records for an apex domain). With Actions deploys, a `CNAME` file in the repo is not needed. Then update `site.ts > siteUrl`, which drives canonical, OG URLs and the sitemap.

## 7. How to update content later (goes into the README)

**Add a project**: edit `src/content/projects.ts` and append:
```ts
{
  kind: 'project', id: 'my-new-project', sections: ['projects'],
  title: 'My New Project', start: '2026', context: 'self-directed',
  summary: 'One line on what it does and why it matters.',
  stack: ['python', 'pytorch'], tags: ['ml'],
  links: [{ label: 'Repo', href: 'https://github.com/KaiwenYangUT/…', kind: 'repo' }],
},
```
Run `npm test && npm run dev`, check `/projects`, then commit and push. The site redeploys in about 1–2 minutes. Newest goes first automatically.

**Add a TA term**: edit `src/content/teaching.ts` and append `{ id: 'sta314-w2027', term: { season: 'Winter', year: 2027 }, courseCode: 'STA314H1', role: 'Teaching Assistant', institution: 'University of Toronto' }`. If the course is new, also add it to `src/content/courses.ts` with the verbatim calendar description, `sourceUrl` and `retrieved` date. The test fails if you forget. The "upcoming" and "now" labels update on their own, and the monthly rebuild refreshes them.

**An entry on two pages** (e.g. a new paid research job): add it once in `work.ts` with `sections: ['work', 'research']` and a `research: {…}` block.

**Swap the photo**: replace `assets-src/portrait-original.jpg`, adjust `portrait.config.json` if the crop changes, then run `npm run photo && npm run og` and commit.

**Change the palette**: edit the token values at the top of `src/styles/tokens.css`. Plum and Ochre are commented in there, ready to paste.
